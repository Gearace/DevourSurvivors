## 一、技术架构

### 1.1 技术栈

| 层级 | 技术选型 | 理由 |
|---|---|---|
| 引擎 | Godot 4.x | 轻量、竖屏适配简单、GDScript 对 AI 友好 |
| 语言 | GDScript | 语法接近 Python，AI 生成代码质量极高 |
| 目标平台 | iOS + Android | 竖屏独占 |
| 渲染 | 2D Canvas | 性能开销低，美术风格灵活 |
| 打包 | Godot 原生导出 | APK ~15MB，远低于 Unity |

### 1.2 架构分层

```
┌─────────────────────────────────────────────┐
│              Presentation 层                  │
│   · 摇杆 UI (Control 节点)                   │
│   · HUD (等级/血条/技能CD)                    │
│   · 升级弹窗 (3选1卡片)                       │
│   · 波次提示动画                              │
├─────────────────────────────────────────────┤
│               Gameplay 层                     │
│   · PlayerController   (移动/吞噬/技能)      │
│   · EnemyAI              (逃跑/游荡/行为树)   │
│   · GestureDetector      (手势识别)           │
│   · SkillSystem          (技能释放/冷却)      │
│   · WaveManager          (波次生成/难度)      │
│   · InscriptionSystem    (浸篆→进化/变异/领域卡)│
│   · MaterialSystem       (五行升级/熔炼/分解)  │
│   · RelicSystem          (遗物道具, 被动增幅)  │
├─────────────────────────────────────────────┤
│                 Data 层                       │
│   · EnemyConfig (Resource)                   │
│   · SkillConfig (Resource)                   │
│   · WaveConfig (Resource)                    │
│   · MaterialConfig (五行/品阶/熔炼背板)       │
│   · CardConfig (进化/变异/领域 三类卡)        │
│   · PlayerStats (单例数据)                    │
├─────────────────────────────────────────────┤
│                 Core 层                       │
│   · GameManager (全局状态机)                  │
│   · ObjectPool (对象池管理)                   │
│   · EventBus (事件总线)                       │
│   · AudioMgr (音频管理)                       │
└─────────────────────────────────────────────┘
```

### 1.3 核心数据流

```
  输入 (手势)
     │
     ▼
  GestureDetector → 解析为 Action 事件
     │
     ▼
  EventBus → 广播事件
     │
     ├── "move_direction: Vector2(x,y)"
     │       ↓
     │   PlayerController → 更新位置
     │
     ├── "skill_swipe: direction, power"
     │       ↓
     │   SkillSystem → 检查冷却 → 执行技能
     │
     ├── "skill_doubleclick: position"
     │       ↓
     │   SkillSystem → 检查冷却 → 执行范围技能
     │
     └── "enemy_eaten: enemy_type, stats"
             ↓
         MaterialSystem → 按敌人类型掉落五行材质(品阶/数量) → 材质库
             ↓
         InscriptionSystem → 技能空间(未浸篆) 与材质 → 局间休整浸篆出 进化/变异/领域 卡
             ↓
         通关弹窗: 抽技能 4选1 → 遗物 3选1(仅精英/Boss 层) → 路线决策 3选1
```

### 1.4 对象池设计

```
敌人对象池:
  · 预分配 50 个敌人节点
  · spawn() 从池中取出或实例化新节点
  · despawn() 回收至池中 (不销毁)
  · clear() 波次结束时回收所有

目的:
  · 避免频繁 new/delete 产生 GC 压力
  · 移动端 60fps 稳定
  · 同屏 100+ 敌人无卡顿
```

## 二、移动端适配策略

### 2.1 分辨率适配

```gdscript
# 全局设置
ProjectSettings.display.window.width  = 720
ProjectSettings.display.window.height = 1280
ProjectSettings.display.stretch.mode  = "2d"
ProjectSettings.display.stretch.aspect = "keep"
```

### 2.2 触控优化

| 参数 | 值 | 说明 |
|---|---|---|
| 摇杆半径 | 60px | 占屏幕宽度的 ~8% |
| 死区 | 10px | 防止微操漂移 |
| 手势灵敏度 | 可调 | 提供设置面板 |
| 振动反馈 | 轻度 | 吞噬/升级/技能释放时 |

### 2.3 竖屏视野补偿

```
问题: 竖屏上方视野窄，顶部敌人不易察觉

解决方案:
  1. 屏幕顶部边缘闪光提示
  2. 敌人靠近顶部时轻微屏幕震动
  3. 顶部 HUD 用高对比色显示危险指示
```

### 2.4 手势识别参数（自设计文档迁入）

```
常量定义:
  TOUCH_DEADZONE        = 10.0 px    # 摇杆有效死区
  SWIPE_MIN_DISTANCE    = 30.0 px    # 划屏最小位移
  SWIPE_MIN_SPEED       = 150.0 px/s # 划屏最小速度
  SWIPE_MAX_DURATION    = 500 ms     # 划屏最大耗时
  DOUBLE_CLICK_WINDOW   = 300 ms     # 双击时间窗口
  DOUBLE_CLICK_RADIUS   = 20.0 px    # 双击位置容差
  JOYSTICK_MAX_RADIUS   = 60.0 px    # 摇杆最大偏移
```

### 2.5 手势优先级（自设计文档迁入）

```
手指按下 → 记录起点和时间
     │
     ▼
手指移动中 → 持续跟踪
     │
     ▼
手指抬起
     │
     ├── 位移 < 30px → 移动指令
     │
     ├── 位移 ≥ 30px 且 速度 > 150px/s → 划屏技能 (指向性)
     │
     └── 位移 < 30px → 等待 250ms 看是否有第二次点击
             │
             ├── 有第二次点击 (在 300ms 内, 距离 < 20px) → 双击技能 (非指向性)
             └── 无第二次点击 → 无效操作
```

**优先级规则：双击 > 划屏 > 拖拽**
- 如果第二次点击同时满足划屏条件，优先判定为双击

## 四、Vibe Coding 执行策略

### 4.1 核心原则

```
1. 一次只生成一个文件
   → 避免 AI 上下文过载导致代码断裂
   → 生成后立即导入 Godot 验证

2. 每个文件自包含、可独立测试
   → joystick.gd 不依赖任何其他脚本
   → gesture_detector.gd 只负责解析手势

3. 用自然语言描述，不用技术术语堆砌
   → "做一个底部居中的圆形摇杆，拖动时里面的小球跟着动"
   → 不说 "继承 Control 节点重写 _input_event 方法"

4. 生成即验证
   → 每次生成后在 Godot 里跑一下
   → 有问题立刻贴报错给 AI 修

5. 先跑通再优化
   → M1 不需要完美的摇杆，能移动就行
   → 细节在 M6 打磨
```

### 4.2 每次对话的 Prompt 结构模板

```
【上下文】
我正在用 Godot 4.x 开发一个竖屏吞噬类游戏。
当前项目结构：[简述已有文件]

【需求】
请帮我生成 [文件名]，功能描述：[自然语言描述]

【技术要求】
- 继承 [基类]
- 使用 [特定API，如 InputEventScreenTouch]
- 需要 [特定考虑，如竖屏适配]

【验证标准】
在 Godot 编辑器中运行后，应该能看到/做到 [具体效果]
```

### 4.3 文件生成顺序

```
M0:  project.godot → game_manager.gd → main_game.tscn
M1:  joystick.tscn/gd → gesture_detector.gd → player.tscn/gd
M2:  enemy_base.gd → enemy_ai.gd → wave_spawner.gd → object_pool.gd
M3:  skill_data.gd → skill_system.gd → skill_effect.gd → skill_visual.tscn
M4:  upgrade_system.gd → upgrade_popup.tscn → fusion_manager.gd
M4:  skill_space.gd → inscription_system.gd → material_system.gd (五行升级/熔炼) → relic_system.gd → interaction_matrix.gd
M5:  enemy_subclasses → boss.gd → route_generator.gd → run_over.gd → audio_mgr.gd
M6:  vfx → screen_shake → profile → export
```

## 五、风险与应对

| 风险 | 概率 | 影响 | 应对方案 |
|---|---|---|---|
| 手势识别在真机上不准 | 中 | 高 | 预留参数调节接口，支持运行时调参 |
| 竖屏上方视野盲区 | 高 | 中 | 屏幕顶部加视觉提示(闪光/震动) |
| 敌人逃跑太聪明导致无聊 | 中 | 高 | 加入 Perlin Noise 扰动 + 边界限制 |
| AI 生成的代码有 Bug | 高 | 低 | 每次生成只测一个文件，快速定位 |
| 移动端性能不足 | 低 | 高 | 对象池 + 控制同屏数 + LOD |
| 浸篆/合成/升级/熔炼 系统过复杂 | 中 | 高 | 先跑通「浸篆→三类卡」主闭环，再逐层加 升级/熔炼/合成 复合材 |
| 三类卡/遗物/材质 数值不平衡 | 中 | 高 | 按 GDD v1.2 四类经典 Build 逐类验证，再全局调优 |

- `difficulty_multiplier` 不再用公式 `1.0 + (wave-1)*0.15`，改为
  `floor_factor[floor] * node_factor[node_type]`，由 `RouteGenerator` 在开层时写入。
- 新增 `run_route` 字段（见上），随 `save_game()` / `load_game()` 序列化。
- 新增 `current_floor: int` 与 `current_node_type: NodeType`。
