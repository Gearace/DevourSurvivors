## 一、核心概念

### 1.1 一句话定位

> **一个在竖屏上单指操控的「反幸存者」游戏 — 你不是在躲避敌人，而是在追逐、吞噬它们。**

### 1.2 核心循环

`
  生成 → 追逐 → 吞噬 → 成长 → 更强
  ↑                              │
  └────── 下一波 ← 升级 ← 吞噬 ←─┘
`

**循环要素：**

| 环节 | 描述 |
|---|---|
| **生成** | 波次自动刷出敌人，敌人类型和数量递增 |
| **追逐** | 玩家通过摇杆移动，主动追击目标敌人 |
| **吞噬** | 接触体型≤玩家的敌人即可吞噬，获得成长 |
| **成长** | 体型增大、属性提升、解锁新技能 |
| **更强** | 能吞噬更大/更多敌人，形成正反馈 |

### 1.3 核心差异化

| 维度 | 传统幸存者 | 吞噬幸存者 |
|---|---|---|
| 玩家行为 | 射击 → 杀怪 | **移动追怪 → 吃掉怪** |
| 敌人行为 | 靠近玩家被击杀 | **主动逃跑，远离玩家** |
| 成长表现 | 武器升级 | **体型增大 + 能力变异** |
| 操作复杂度 | 双摇杆 (移动+瞄准) | **单摇杆 + 手势** |
| 策略深度 | 武器搭配 | **卡牌构筑 + 融合进化** |

## 二、操作设计

### 2.1 屏幕布局

`
┌──────────────────────────────────┐
│        技能状态栏                 │   ← 顶部窄条 (~10%)
│  [Lv.3] [HP ███░░] [能量 ▓▓▓░]   │
├──────────────────────────────────┤
│                                  │
│         游戏主画面               │   ← 中部 (~75%)
│    (角色 + 敌人 + 特效)           │
│                                  │
├──────────────────────────────────┤
│       ┌────────────┐             │
│       │  虚拟摇杆   │             │   ← 底部正中 (~15%)
│       │ (半径~60px) │             │
│       └────────────┘             │
│                                  │
└──────────────────────────────────┘
`

**核心约束：**
- 竖屏 9:16，底部正中间仅有一个虚拟摇杆
- 没有任何额外按钮、开关、跳跃键
- 所有交互（移动 + 技能释放）均在摇杆内完成

### 2.2 手势矩阵

| 手势 | 触发条件 | 效果 | 冷却 |
|---|---|---|---|
| **拖拽移动** | 手指在摇杆内拖动，位移 < 30px 或速度 ≤ 150px/s | 角色朝拖拽方向移动 | 无 |
| **快速划过** | 摇杆内单次滑动，位移 ≥ 30px 且速度 > 150px/s | 沿划动方向释放**指向性技能** | 3-6s |
| **双击** | 摇杆内两次点击，间隔 < 300ms 且位置距离 < 20px | 释放**非指向性范围技能** | 6-15s |

### 2.3 手势识别参数

`
常量定义:
  TOUCH_DEADZONE        = 10.0 px    # 摇杆有效死区
  SWIPE_MIN_DISTANCE    = 30.0 px    # 划屏最小位移
  SWIPE_MIN_SPEED       = 150.0 px/s # 划屏最小速度
  SWIPE_MAX_DURATION    = 500 ms     # 划屏最大耗时
  DOUBLE_CLICK_WINDOW   = 300 ms     # 双击时间窗口
  DOUBLE_CLICK_RADIUS   = 20.0 px    # 双击位置容差
  JOYSTICK_MAX_RADIUS   = 60.0 px    # 摇杆最大偏移
`

### 2.4 手势优先级

`
手指按下 → 记录起点和时间
    │
    ▼
手指移动中 → 持续跟踪
    │
    ▼
手指抬起
    │
    ├── 位移 < 30px → 移动指令
    │
    ├── 位移 ≥ 30px 且 速度 > 150px/s → 划屏技能 (指向性)
    │
    └── 位移 < 30px → 等待 250ms 看是否有第二次点击
            │
            ├── 有第二次点击 (在 300ms 内, 距离 < 20px) → 双击技能 (非指向性)
            └── 无第二次点击 → 无效操作
`

**优先级规则：双击 > 划屏 > 拖拽**
- 如果第二次点击同时满足划屏条件，优先判定为双击

## 三、吞噬与敌人系统

### 3.1 吞噬判定

`
吞噬条件:
  玩家体型 ≥ 敌人体型 × 0.8 → 接触即吞噬
  玩家体型 <  敌人体型 × 0.8 → 不能吞噬，碰撞弹开/扣血

设 0.8 阈值的原因:
  → 给玩家"能吃"的安全感
  → 略微小于玩家的敌人也能吞，增加爽快感
  → 保留"有些敌人暂时不能吃"的策略性
`

### 3.2 敌人类型

| 类型 | 颜色 | 体型倍率 | 行为特征 | 吞噬收益 |
|---|---|---|---|---|
| **小兵** | 绿色 | 1.0x | 正常逃跑，速度中等 | +1 体型 |
| **迅捷** | 黄色 | 0.8x | 逃跑速度快，转向笨拙 | +0.5 体型 |
| **重装** | 红色 | 1.5x | 逃跑慢，玩家需先成长才能吃 | +3 体型 |
| **分裂** | 紫色 | 1.2x | 被吞噬时分裂成 2 个小兵 | +1.5 (实际得 3) |
| **诱饵** | 粉色 | 2.0x | 看起来很大，靠近后缩小逃跑 | 陷阱 |
| **Boss** | 金色 | 5.0x | 每波最后出现，有技能 | +10 体型 |

### 3.3 敌人逃跑 AI

`
行为树:

  检测与玩家距离
    │
    ├── < R1 (80px) → 全力逃跑
    │                  速度 = 最高速 × 1.3
    │                  加入随机急转弯 (Perlin Noise 扰动)
    │
    ├── < R2 (200px) → 常规逃跑
    │                  速度 = 最高速 × 1.0
    │                  稳定远离玩家
    │
    └── ≥ R2 → 游荡模式
                   速度 = 最高速 × 0.3
                   随机方向移动 + 缓慢转向

  边界处理:
    · 碰到屏幕边缘 → 沿边缘滑动，不卡住
    · 角落 → 优先逃离角落方向
    · 群体逃跑时有一定聚集倾向 (模拟 herd behavior)
`

## 四、主动技能系统

### 4.1 技能获取方式

| 来源 | 概率 | 说明 |
|---|---|---|
| 升级时 3选1 | 固定 | 从主动技能池中随机抽取 |
| 吞噬特定敌人 | 10-30% | 概率掉落对应技能 |
| Boss 掉落 | 100% | 击败 Boss 必得 |
| 初始自带 | 1个 | 吞噬波 (指向性) |

### 4.2 指向性技能（划屏释放）

| 技能名 | 描述 | 冷却 | 升级效果 |
|---|---|---|---|
| **吞噬波** | 沿划动方向发射吞噬光束，吃掉路径上所有体型≤玩家的敌人 | 3s | 宽度+20% / 长度+20% |
| **螺旋吞噬** | 以玩家为中心旋转一圈，吞噬周围敌人 | 4s | 圈数+1 / 半径+15% |
| **追踪吞噬** | 释放追踪弹，自动追踪最近敌人并吞噬 | 5s | 弹数+2 / 追踪速度+20% |
| **黑洞牵引** | 在划动终点生成小型黑洞，持续吸入并吞噬敌人 | 6s | 持续时间+1s / 引力半径+30% |
| **相位切割** | 沿划动方向产生切割线，无视体型差吞噬线性敌人 | 4s | 线长+50% / 可穿透+1 |

### 4.3 非指向性技能（双击释放）

| 技能名 | 描述 | 冷却 | 升级效果 |
|---|---|---|---|
| **影分身之术** | 生成分身，分身自动吞噬路径上的敌人，吞噬计入玩家 | 8s | 分身数量+2 / 持续时间+2s |
| **影子束缚术** | 范围内敌人被影子缠绕，3s内无法移动且暴露弱点 | 10s | 范围+30% / 持续时间+1s |
| **镜像领域** | 创造镜像空间，所有进入的敌人被复制一份(你的) | 12s | 复制倍数+1 / 存在时间+3s |
| **时空停滞** | 全屏敌人冻结，期间玩家可以自由吞噬 | 15s | 冻结时间+1s / 解冻后眩晕1s |
| **群体拉近** | 范围内所有敌人强制拉向玩家中心 | 6s | 范围+40% / 拉力+30% |
| **吞噬光环** | 持续期间，周围范围内敌人每秒受到吞噬伤害 | 10s | 伤害+50% / 半径+20% |

## 六、升级与抽卡机制

### 6.1 升级触发

`
升级条件:
  累计吞噬 N 个敌人 → 升级
  N 的计算公式:  N = base × (1.1 ^ level)
  即每级所需吞噬数递增 10%

升级弹窗:
  · 暂停游戏 (敌人继续移动但不再攻击)
  · 从技能池中抽取 4-6 张卡牌
  · 玩家选择 1 张加入牌组
  · 确认后恢复游戏
`

### 6.2 抽卡算法

`
稀有度权重 (随等级变化):

  Lv.1-5:
    普通  70% | 稀有  25% | 传说  4%  | 遗物  1%

  Lv.6-15:
    普通  50% | 稀有  35% | 传说  12% | 遗物  3%

  Lv.16+:
    普通  30% | 稀有  40% | 传说  20% | 遗物  10%

保底机制:
  · 连续 10 次未出传说 → 下次必定出传说
  · 连续 5 次未出遗物 → 下次必定出遗物

流派引导:
  · 如果玩家已有某核心卡，提高其共鸣卡的抽取概率

## 八、技术架构

### 8.1 技术栈

| 层级 | 技术选型 | 理由 |
|---|---|---|
| 引擎 | Godot 4.x | 轻量、竖屏适配简单、GDScript 对 AI 友好 |
| 语言 | GDScript | 语法接近 Python，AI 生成代码质量极高 |
| 目标平台 | iOS + Android | 竖屏独占 |
| 渲染 | 2D Canvas | 性能开销低，美术风格灵活 |
| 打包 | Godot 原生导出 | APK ~15MB，远低于 Unity |

### 8.2 架构分层

`
┌─────────────────────────────────────────────┐
│              Presentation 层                  │
│   · 摇杆 UI (Control 节点)                   │
│   · HUD (等级/血条/技能CD)                    │
│   · 升级弹窗 (3选1卡片)                       │
│   · 波次提示动画                              │
├─────────────────────────────────────────────┤
│               Gameplay 层                     │
│   · PlayerController   (移动/吞噬/技能)      │
│   · EnemyAI              (逃跑/游荡/行为树)   │
│   · GestureDetector      (手势识别)           │
│   · SkillSystem          (技能释放/冷却)      │
│   · WaveManager          (波次生成/难度)      │
│   · UpgradeSystem        (升级/牌组/融合)     │
├─────────────────────────────────────────────┤
│                 Data 层                       │
│   · EnemyConfig (Resource)                   │
│   · SkillConfig (Resource)                   │
│   · WaveConfig (Resource)                    │
│   · PlayerStats (单例数据)                    │
├─────────────────────────────────────────────┤
│                 Core 层                       │
│   · GameManager (全局状态机)                  │
│   · ObjectPool (对象池管理)                   │
│   · EventBus (事件总线)                       │
│   · AudioMgr (音频管理)                       │
└─────────────────────────────────────────────┘
`

### 8.3 核心数据流

`
  输入 (手势)
     │
     ▼
  GestureDetector → 解析为 Action 事件
     │
     ▼
  EventBus → 广播事件
     │
     ├── "move_direction: Vector2(x,y)"
     │       ↓
     │   PlayerController → 更新位置
     │
     ├── "skill_swipe: direction, power"
     │       ↓
     │   SkillSystem → 检查冷却 → 执行技能
     │
     ├── "skill_doubleclick: position"
     │       ↓
     │   SkillSystem → 检查冷却 → 执行范围技能
     │
     └── "enemy_eaten: enemy_type, stats"
             ↓
         UpgradeSystem → 更新属性 → 检查升级
             ↓
         EventBus → "level_up" 事件
             ↓
         HUD → 显示升级弹窗
`

### 8.4 对象池设计

`
敌人对象池:
  · 预分配 50 个敌人节点
  · spawn() 从池中取出或实例化新节点
  · despawn() 回收至池中 (不销毁)
  · clear() 波次结束时回收所有

目的:
  · 避免频繁 new/delete 产生 GC 压力
  · 移动端 60fps 稳定
  · 同屏 100+ 敌人无卡顿
`

## 十一、Vibe Coding 执行策略

### 11.1 核心原则

`
1. 一次只生成一个文件
   → 避免 AI 上下文过载导致代码断裂
   → 生成后立即导入 Godot 验证

2. 每个文件自包含、可独立测试
   → joystick.gd 不依赖任何其他脚本
   → gesture_detector.gd 只负责解析手势

3. 用自然语言描述，不用技术术语堆砌
   → "做一个底部居中的圆形摇杆，拖动时里面的小球跟着动"
   → 不说 "继承 Control 节点重写 _input_event 方法"

4. 生成即验证
   → 每次生成后在 Godot 里跑一下
   → 有问题立刻贴报错给 AI 修

5. 先跑通再优化
   → M1 不需要完美的摇杆，能移动就行
   → 细节在 M6 打磨
`

### 11.2 每次对话的 Prompt 结构模板

`
【上下文】
我正在用 Godot 4.x 开发一个竖屏吞噬类游戏。
当前项目结构：[简述已有文件]

【需求】
请帮我生成 [文件名]，功能描述：[自然语言描述]

【技术要求】
- 继承 [基类]
- 使用 [特定API，如 InputEventScreenTouch]
- 需要 [特殊考虑，如竖屏适配]

【验证标准】
在 Godot 编辑器中运行后，应该能看到/做到 [具体效果]
`

| 风险 | 概率 | 影响 | 应对方案 |
|---|---|---|---|
| 手势识别在真机上不准 | 中 | 高 | 预留参数调节接口，支持运行时调参 |
| 竖屏上方视野盲区 | 高 | 中 | 屏幕顶部加视觉提示(闪光/震动) |
| 敌人逃跑太聪明导致无聊 | 中 | 高 | 加入 Perlin Noise 扰动 + 边界限制 |
| AI 生成的代码有 Bug | 高 | 低 | 每次生成只测一个文件，快速定位 |
| 移动端性能不足 | 低 | 高 | 对象池 + 控制同屏数 + LOD |
| 融合系统过于复杂 | 中 | 中 | 先实现基础融合，逐步扩展配方 |
| 卡牌池不平衡 | 中 | 高 | 每完成一批卡牌即进行测试验证 |

## 附录 B: 术语表

| 术语 | 含义 |
|---|---|
| 吞噬 | 玩家接触并吃掉敌人，获得成长 |
| 指向性技能 | 需要玩家指定方向的技能 (划屏释放) |
| 非指向性技能 | 以玩家为中心的 range 技能 (双击释放) |
| 核心卡 | 改变玩法本质的被动技能 |
| 组件卡 | 提供数值/属性增益的被动技能 |
| 共鸣卡 | 与其他卡牌产生 Combo 效果的被动技能 |
| 遗物卡 | 全局特殊效果，不可替换 |
| 融合 | 两张特定卡牌组合产生更强新卡牌 |
| Build | 玩家通过卡牌组合形成的独特玩法流派 |
| 牌组 | 玩家当前持有的所有被动卡牌集合 |
