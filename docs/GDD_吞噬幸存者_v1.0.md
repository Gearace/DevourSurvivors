## 一、核心概念

### 1.1 一句话定位

> **一个在竖屏上单指操控的「反幸存者」游戏 — 你不是在躲避敌人，而是在追逐、吞噬它们。**

### 1.2 核心循环

`
  生成 → 追逐 → 吞噬 → 成长 → 更强
  ↑                              │
  └────── 下一波 ← 升级 ← 吞噬 ←─┘
`

**循环要素：**

| 环节 | 描述 |
|---|---|
| **生成** | 波次自动刷出敌人，敌人类型和数量递增 |
| **追逐** | 玩家通过摇杆移动，主动追击目标敌人 |
| **吞噬** | 接触体型≤玩家的敌人即可吞噬，获得成长 |
| **成长** | 体型增大、属性提升、解锁新技能 |
| **更强** | 能吞噬更大/更多敌人，形成正反馈 |

### 1.3 核心差异化

| 维度 | 传统幸存者 | 吞噬幸存者 |
|---|---|---|
| 玩家行为 | 射击 → 杀怪 | **移动追怪 → 吃掉怪** |
| 敌人行为 | 靠近玩家被击杀 | **主动逃跑，远离玩家** |
| 成长表现 | 武器升级 | **体型增大 + 能力变异** |
| 操作复杂度 | 双摇杆 (移动+瞄准) | **单摇杆 + 手势** |
| 策略深度 | 武器搭配 | **卡牌构筑 + 融合进化** |

## 二、操作设计

### 2.1 屏幕布局

`
┌──────────────────────────────────┐
│        技能状态栏                 │   ← 顶部窄条 (~10%)
│  [Lv.3] [HP ███░░] [能量 ▓▓▓░]   │
├──────────────────────────────────┤
│                                  │
│         游戏主画面               │   ← 中部 (~75%)
│    (角色 + 敌人 + 特效)           │
│                                  │
├──────────────────────────────────┤
│       ┌────────────┐             │
│       │  虚拟摇杆   │             │   ← 底部正中 (~15%)
│       │ (半径~60px) │             │
│       └────────────┘             │
│                                  │
└──────────────────────────────────┘
`

**核心约束：**
- 竖屏 9:16，底部正中间仅有一个虚拟摇杆
- 没有任何额外按钮、开关、跳跃键
- 所有交互（移动 + 技能释放）均在摇杆内完成

### 2.2 手势矩阵

| 手势 | 触发条件 | 效果 | 冷却 |
|---|---|---|---|
| **拖拽移动** | 手指在摇杆内拖动，位移 < 30px 或速度 ≤ 150px/s | 角色朝拖拽方向移动 | 无 |
| **快速划过** | 摇杆内单次滑动，位移 ≥ 30px 且速度 > 150px/s | 沿划动方向释放**指向性技能** | 3-6s |
| **双击** | 摇杆内两次点击，间隔 < 300ms 且位置距离 < 20px | 释放**非指向性范围技能** | 6-15s |

### 2.3 手势识别参数

`
常量定义:
  TOUCH_DEADZONE        = 10.0 px    # 摇杆有效死区
  SWIPE_MIN_DISTANCE    = 30.0 px    # 划屏最小位移
  SWIPE_MIN_SPEED       = 150.0 px/s # 划屏最小速度
  SWIPE_MAX_DURATION    = 500 ms     # 划屏最大耗时
  DOUBLE_CLICK_WINDOW   = 300 ms     # 双击时间窗口
  DOUBLE_CLICK_RADIUS   = 20.0 px    # 双击位置容差
  JOYSTICK_MAX_RADIUS   = 60.0 px    # 摇杆最大偏移
`

### 2.4 手势优先级

`
手指按下 → 记录起点和时间
    │
    ▼
手指移动中 → 持续跟踪
    │
    ▼
手指抬起
    │
    ├── 位移 < 30px → 移动指令
    │
    ├── 位移 ≥ 30px 且 速度 > 150px/s → 划屏技能 (指向性)
    │
    └── 位移 < 30px → 等待 250ms 看是否有第二次点击
            │
            ├── 有第二次点击 (在 300ms 内, 距离 < 20px) → 双击技能 (非指向性)
            └── 无第二次点击 → 无效操作
`

**优先级规则：双击 > 划屏 > 拖拽**
- 如果第二次点击同时满足划屏条件，优先判定为双击

## 三、吞噬与敌人系统

### 3.1 吞噬判定

`
吞噬条件:
  玩家体型 ≥ 敌人体型 × 0.8 → 接触即吞噬
  玩家体型 <  敌人体型 × 0.8 → 不能吞噬，碰撞弹开/扣血

设 0.8 阈值的原因:
  → 给玩家"能吃"的安全感
  → 略微小于玩家的敌人也能吞，增加爽快感
  → 保留"有些敌人暂时不能吃"的策略性
`

### 3.2 吞噬四层机制（门槛 / 进度 / 反噬 / 资源）

> 设计目标：让「吞」拥有武器系统里的「消耗与压力」，而不只是「吃就变大」。

「吞」没有 HP 条，但有它的等价物——四个维度一起支撑战斗感：

| 武器系统里 | 吞噬系统里 | 维度 | 作用 |
|---|---|---|---|
| 打不过要磨血 | 够格才咬得动（体型门槛） | **门槛** | 决定能不能啃 |
| 持续输出磨血 | 大怪要持续啃 N 秒才吞下 | **进度** | 决定啃多久 |
| 走位失误吃伤害 | 撞到比自己大的怪 → 你受伤 | **反噬** | 危险层 |
| 技能费能量/卡 CD | 啃大怪持续耗能量，啃不动 | **资源管理** | 节奏决策 |

#### 3.2.1 体型门槛（能不能吞）

- 保留现有 0.8 倍规则：`玩家体型 ≥ 敌人体型 × 0.8` 才能接触即吞。
- 够格的敌人（小怪/迅捷）= 一口吞，维持爽感，不消耗能量。
- 不够格的（重装/分裂/诱饵/Boss）= 需「啃食进度」，且啃食期间有反噬。
- 是否能吃更大的怪，最终由**等级/卡牌**决定（如「虚空吞噬」），不是纯半径比对。体型是成长表现，不是唯一通行证。

#### 3.2.2 啃食进度（吞多久）

- 大怪/Boss 不能一口吞，需**咬住啃 N 秒**才吞下；期间它继续挣扎逃，甚至反噬。
- 视觉：敌人身上出现**环形啃食进度条**（替代血条），填满即被吞下。
- 啃食时长随敌人体型递增，Boss 最长（形成 boss 战节奏）。
- 节奏设计：小怪一口吞（爽）→ 大怪啃 N 秒（紧，会反噬）→ Boss 啃更久（boss 战），循环成「爽-紧-爽」。

#### 3.2.3 反噬（啃的时候你疼不疼）

- 撞到/啃比自己大的怪时，敌人反噬扣你血并把你推开（现有 0.5s 无敌帧机制可复用）。
- 这是「危险层」：玩家不能无脑贴大怪，必须权衡。

#### 3.2.4 资源管理（能量 = 啃食的燃料）

- 把「能量」做成**啃食燃料**：啃大怪/Boss 时**持续消耗**能量（如每秒 -1~-2）。
- 小怪一口吞**不耗能量**（维持爽感）。
- 能量见底 → 啃不动大怪，只能先吞小怪回能量（「吞小怪回能量」即「能量虹吸」卡的原始效果，正好接上）。
- 产生节奏决策：`攒能量 → 咬住大怪 → 一边啃一边被反噬扣血 → 啃完拿收益 → 能量空了退回吞小怪回能`。
- 与卡牌「虚空之眼」（技能耗能量、每 5s 回 1）同源，统一能量体系。

#### 3.2.5 敌人类型 → 机制映射

| 类型 | 体型倍率 | 一口吞 | 啃食 | 反噬 | 能量 | 吞噬收益 |
|---|---|---|---|---|---|---|
| **小兵** | 1.0x | ✅ | 无 | 无 | 不耗 | +1 体型 / +1 能量 |
| **迅捷** | 0.8x | ✅ | 无 | 无 | 不耗 | +0.5 体型 |
| **重装** | 1.5x | ❌ | 短啃 (~2s) | 啃食时被推开 | 慢耗 | +3 体型 |
| **分裂** | 1.2x | ❌ | 中啃 (~3s) | 无 | 慢耗 | +1.5 (吞下时分裂 2 小兵) |
| **诱饵** | 2.0x | ❌ | 中啃 | 靠近后缩小逃跑 | 中耗 | 陷阱（几乎无收益） |
| **Boss** | 5.0x | ❌ | 长啃 (boss 战) | 强反噬 | 高耗 | +10 体型 / 必掉卡 |

### 3.3 敌人类型

| 类型 | 颜色 | 体型倍率 | 行为特征 | 吞噬收益 |
|---|---|---|---|---|
| **小兵** | 绿色 | 1.0x | 正常逃跑，速度中等 | +1 体型 |
| **迅捷** | 黄色 | 0.8x | 逃跑速度快，转向笨拙 | +0.5 体型 |
| **重装** | 红色 | 1.5x | 逃跑慢，玩家需先成长才能吃 | +3 体型 |
| **分裂** | 紫色 | 1.2x | 被吞噬时分裂成 2 个小兵 | +1.5 (实际得 3) |
| **诱饵** | 粉色 | 2.0x | 看起来很大，靠近后缩小逃跑 | 陷阱 |
| **Boss** | 金色 | 5.0x | 每波最后出现，有技能 | +10 体型 |

> 注：各类型在「一口吞 / 啃食 / 反噬 / 能量」上的差异见 3.2.5 映射表。

### 3.4 敌人逃跑 AI

`
行为树:

  检测与玩家距离
    │
    ├── < R1 (80px) → 全力逃跑
    │                  速度 = 最高速 × 1.3
    │                  加入随机急转弯 (Perlin Noise 扰动)
    │
    ├── < R2 (200px) → 常规逃跑
    │                  速度 = 最高速 × 1.0
    │                  稳定远离玩家
    │
    └── ≥ R2 → 游荡模式
                   速度 = 最高速 × 0.3
                   随机方向移动 + 缓慢转向

  边界处理:
    · 碰到屏幕边缘 → 沿边缘滑动，不卡住
    · 角落 → 优先逃离角落方向
    · 群体逃跑时有一定聚集倾向 (模拟 herd behavior)
`

### 5.2 融合进化系统

`
当玩家同时持有两张特定卡牌时，自动触发融合进化。
融合产物取代两张原料牌，视觉上合并为一个效果。
融合产物不能再参与二次融合（防止无限链）。
`

## 六、成长与抽卡机制 (无职业 · 无经验 · 卡牌构筑驱动)

### 6.1 设计原则

`
· 无职业、无经验、无等级系统
· 成长完全来自卡牌构筑 (build)
· 两张独立牌组: 进化卡 (主动技能) + 遗物卡 (被动构筑)
· 五行材质 (金/木/水/火/土) 决定进化卡能跟谁融合/镶嵌
· 元素增幅 (风/火/水/土/雷/光/暗) 由遗物卡提供, 放大技能威力
· 两套体系独立, 同名不等同 (五行火 ≠ 奇幻火)
`

### 6.2 进化卡 (Evolution Card)

主动技能, 可融合/镶嵌, 通关奖励 4 选 1。

`
材质 (五行, 5 种):
  · 金: 攻速/攻击力↑, +雷系效果×
  · 木: 成长/回复↑, +木系×
  · 水: 控制/减速↑, +水系×
  · 火: 持续伤害/灼烧↑, +火系×
  · 土: 减伤/护甲↑, +土系×

技能池 (取自 GDD 第四章):
  · 吞噬波 / 螺旋吞噬 / 追踪吞噬 / 黑洞牵引 / 相位切割
  · 影分身之术 / 影子束缚术 / 镜像领域 / 时空停滞
  · 群体拉近 / 吞噬光环

池子 = 11 技能 × 5 材质 = 55 张
`

#### 进化卡融合/镶嵌

同类融合 (两张同材质进化卡):
`
· 威力 ×1.4 + 材质专属加成
· 例: 吞噬波(金) + 相位切割(金) → 熔金裂刃 (金系重斩, 范围+50%)
`

相生镶嵌 (两张相生材质进化卡, 按五行相生):
`
相生链: 木生火 → 火生土 → 土生金 → 金生水 → 水生木
· 基础威力不变, 解锁该相生对独有机制
· 例: 永恒之木(木·成长) + 星星之火(火·持续) → 木生火
  → 成品的"火"技能持续时间 +50% (木的"成长"注入火)
· 例: 深渊之钵(金·锋利) + 毒沼之水(水·控制) → 金生水
  → 成品的"水"技能控制生效时间 +50% (金的"锋利"注入水)
`

### 6.3 遗物卡 (Relic Card)

被动构筑, 不可融合, 按稀有度分档, 精英层/Boss 层通关掉落 + 商店购买。

`
稀有度 (5 档):
  普通 / 罕见 / 史诗 / 传说 / 神器

效果池:
  · 血量类: 最大生命+ / 开局回满 / 低血回血
  · 能量类: 能量上限+ / 回能速度+
  · 状态 buff: 开局无敌 / 啃食进度加快 / 挣脱率↓
  · 状态 debuff (给敌人): 减速 / 流血 / 易伤
  · 材质抗性: 对某五行材质技能减伤/免疫
  · 元素增幅: 放大某元素技能威力 (×1.5)

掉落规则:
  普通层:  只给进化卡 4 选 1
  精英层:  进化卡 4 选 1 + 遗物卡 3 选 1 (稀有度 roll: 普通 60% / 罕见 30% / 史诗 9% / 传说 1%)
  Boss 层:  进化卡 4 选 1 + 遗物卡 3 选 1 (保底 1 张史诗以上, 其余 2 张偏高稀有度)
`

### 6.4 通关奖励顺序

`
清完当前层怪
  → 进化卡 4 选 1 (所有层)
  → 遗物卡 3 选 1 (精英层/Boss 层, 稀有度按关卡 roll)
  → 路线决策 3 选 1 (进下一层)
`

### 6.5 材质掉落 (怪物掉材质, 无经验系统)

材质是稀有资源, 不能太常见也不能太稀缺。

`
掉落概率 (按敌人类型):
  · basic / swift / decoy: 不掉材质
  · heavy:  30% 掉 1 个, 材质类型 5 种均等
  · split:  40% 掉 1 个, 材质类型 5 种均等
  · 精英:   100% 掉 1~2 个, 50% 偏向精英属性 + 50% 随机
  · Boss:   100% 掉 2~3 个, 偏向 Boss 属性

一局 13 层约拿到 8~12 个材质。
"集齐一对能镶嵌" 是局内目标感, 不是必成。
`

### 6.6 无经验成长曲线

没经验了, 玩家"变强"靠三样:
`
1. 进化卡数量/融合: 技能多、融合强 → 输出涨
2. 遗物卡: 数值 buff 叠 → 血/能/抗性涨
3. 材质共鸣: 同材质卡越多, 该材质效果有额外堆叠
   (同材质 ×1.1/张, 软上限: 同材质 5 张后不再堆叠)
`

## 七、波次与难度曲线 — 路线化关卡（StS 结构 × Roll）

> 本章节替代原 7.1/7.2。参考杀戮尖塔「章节节点结构」，但节奏压缩到移动端：
> 一局 = 一个章节（13 层）；每层 = 一个节点；层内 3 选 1 路线（roll 机制）；
> 难度由「层号」与「节点类型」双维度决定，而非单纯时间流逝。

### 7.1 节点类型定义

| 节点类型 | 图标 | 说明 | 难度系数 |
|---|---|---|---|
| 普通波 | ⚔️ | 标准敌人编队，考验操作 | ×1.0 |
| 精英 | 💀 | 高难特殊精英 + 护卫，必掉稀有奖励 | ×1.6 |
| 营地 | 🏕️ | 安全节点，三选一增益 | ×0.3 |
| 商店 | 🏪 | 花分数购买卡牌/遗物/回复 | ×0.5 |
| 事件 | ❓ | 随机剧情事件，二选一 | 视事件 |
| Boss | 👑 | 层13 强制战，通关节点 | ×2.0 |

### 7.2 13 层路线结构（模板）

```
层  1 → 普通波（固定，新手引导）
层  2 → 普通波（固定）
层  3 → 3选1：[普通波] [精英] [营地]
层  4 → 普通波（固定）
层  5 → 3选1：[普通波] [精英] [商店]
层  6 → 普通波（固定）
层  7 → 3选1：[精英] [事件] [营地]
层  8 → 普通波（固定）
层  9 → 3选1：[精英] [商店] [事件]
层 10 → 3选1：[精英] [营地] [普通波]
层 11 → 3选1：[精英] [事件] [营地]
层 12 → 3选1：[精英] [商店] [营地]
层 13 → Boss（固定，章节 Boss）
```

**Roll 机制（路线 C）**：
- 每局开始时按模板 roll 出 13 层的完整节点序列（约束：全章最多 2 个精英、
  精英不出现在层 2、商店至少 1 个）。
- roll 结果全局固定并写入 save。
- HUD 提供「路线」按钮：展开时预览**后 1-2 层**的节点类型；
  当前层的 3 张候选卡片以 3 选 1 卡片横排呈现。
- 清完当前层节点后进入「决策时刻」：游戏暂停，玩家点击其中一张卡进入下一节点。

### 7.4 难度双维度模型

```
节点总难度 = 层号系数 × 节点类型系数 × 节奏修正

层号系数（手调台阶，前松后紧）:
  层 1-4   → 1.0
  层 5-6   → 1.15
  层 7-8   → 1.30
  层 9-10  → 1.50
  层 11-12 → 1.75
  层 13    → 2.0（Boss）

节点类型系数:
  普通波 1.0 / 精英 1.6 / 营地 0.3 / 商店 0.5 / 事件(战斗) 1.2 / 事件(剧情) 0.5

节奏修正:
  连续 2 层选营地/商店 → 下一普通波 ×1.2（防全安全路线）
  连续 2 层选精英     → 解锁 1 次免费营地（补偿高风险）
```

> 实现：`GameManager.difficulty_multiplier` 从公式 `1.0 + (wave-1)*0.15`
> 改为查层号系数表 × 当前节点类型系数。
> 敌人数量/速度/AI 按层号系数缩放；精英/Boss 按自身体型 + 节点系数额外缩放。

### 7.5 章节与无尽模式

```
章节 1: 13 层，基础敌人，Boss = 金甲兽
章节 2: 13 层，敌人速度 +20%，新增「佯攻」AI，Boss = 虚空吞噬者
章节 3: 13 层，新增 2 种敌人类型，Boss = 深渊巨口
章节 4+: 无尽模式，Boss 体型 ×1.5，敌人全属性 ×1.25
```

- 章节间保留 build（卡牌不重置），HP/能量回复至 70%。
- 无尽模式每 13 层为一章，循环递增。

| 融合系统 | 精英掉传说卡 → 更易触发融合；商店补融合原料 |
| 对象池 | 精英/事件敌人走对象池，不单独管理 |
| 难度系数 | `difficulty_multiplier` 改为「层号 × 节点类型」双值查表 |
| 死亡 | `player_died` → run over 界面（得分/最高层/永恒之环保留 1 卡） |
| 分数 | 商店货币即现有 score；Boss 通关 +200 分 |

## 八、技术架构

### 8.1 技术栈

| 层级 | 技术选型 | 理由 |
|---|---|---|
| 引擎 | Godot 4.x | 轻量、竖屏适配简单、GDScript 对 AI 友好 |
| 语言 | GDScript | 语法接近 Python，AI 生成代码质量极高 |
| 目标平台 | iOS + Android | 竖屏独占 |
| 渲染 | 2D Canvas | 性能开销低，美术风格灵活 |
| 打包 | Godot 原生导出 | APK ~15MB，远低于 Unity |

### 8.2 架构分层

`
┌─────────────────────────────────────────────┐
│              Presentation 层                  │
│   · 摇杆 UI (Control 节点)                   │
│   · HUD (等级/血条/技能CD)                    │
│   · 升级弹窗 (3选1卡片)                       │
│   · 波次提示动画                              │
├─────────────────────────────────────────────┤
│               Gameplay 层                     │
│   · PlayerController   (移动/吞噬/技能)      │
│   · EnemyAI              (逃跑/游荡/行为树)   │
│   · GestureDetector      (手势识别)           │
│   · SkillSystem          (技能释放/冷却)      │
│   · WaveManager          (波次生成/难度)      │
│   · UpgradeSystem        (升级/牌组/融合)     │
├─────────────────────────────────────────────┤
│                 Data 层                       │
│   · EnemyConfig (Resource)                   │
│   · SkillConfig (Resource)                   │
│   · WaveConfig (Resource)                    │
│   · PlayerStats (单例数据)                    │
├─────────────────────────────────────────────┤
│                 Core 层                       │
│   · GameManager (全局状态机)                  │
│   · ObjectPool (对象池管理)                   │
│   · EventBus (事件总线)                       │
│   · AudioMgr (音频管理)                       │
└─────────────────────────────────────────────┘
`

### 8.3 核心数据流

`
  输入 (手势)
     │
     ▼
  GestureDetector → 解析为 Action 事件
     │
     ▼
  EventBus → 广播事件
     │
     ├── "move_direction: Vector2(x,y)"
     │       ↓
     │   PlayerController → 更新位置
     │
     ├── "skill_swipe: direction, power"
     │       ↓
     │   SkillSystem → 检查冷却 → 执行技能
     │
     ├── "skill_doubleclick: position"
     │       ↓
     │   SkillSystem → 检查冷却 → 执行范围技能
     │
     └── "enemy_eaten: enemy_type, stats"
             ↓
         UpgradeSystem → 更新属性 → 检查升级
             ↓
         EventBus → "level_up" 事件
             ↓
         HUD → 显示升级弹窗
`

### 8.4 对象池设计

`
敌人对象池:
  · 预分配 50 个敌人节点
  · spawn() 从池中取出或实例化新节点
  · despawn() 回收至池中 (不销毁)
  · clear() 波次结束时回收所有

目的:
  · 避免频繁 new/delete 产生 GC 压力
  · 移动端 60fps 稳定
  · 同屏 100+ 敌人无卡顿
`

## 十一、Vibe Coding 执行策略

### 11.1 核心原则

`
1. 一次只生成一个文件
   → 避免 AI 上下文过载导致代码断裂
   → 生成后立即导入 Godot 验证

2. 每个文件自包含、可独立测试
   → joystick.gd 不依赖任何其他脚本
   → gesture_detector.gd 只负责解析手势

3. 用自然语言描述，不用技术术语堆砌
   → "做一个底部居中的圆形摇杆，拖动时里面的小球跟着动"
   → 不说 "继承 Control 节点重写 _input_event 方法"

4. 生成即验证
   → 每次生成后在 Godot 里跑一下
   → 有问题立刻贴报错给 AI 修

5. 先跑通再优化
   → M1 不需要完美的摇杆，能移动就行
   → 细节在 M6 打磨
`

### 层号 / 节点类型难度系数表

```gdscript
var floor_factor: Dictionary = {
    1: 1.0, 2: 1.0, 3: 1.0, 4: 1.0,
    5: 1.15, 6: 1.15,
    7: 1.30, 8: 1.30,
    9: 1.50, 10: 1.50,
    11: 1.75, 12: 1.75,
    13: 2.0,
}
var node_factor: Dictionary = {
    NodeType.Normal: 1.0,
    NodeType.Elite:  1.6,
    NodeType.Camp:   0.3,
    NodeType.Shop:   0.5,
    NodeType.Event:  1.2,   # 战斗事件；剧情事件 0.5
    NodeType.Boss:   2.0,
}
# 实际难度 = floor_factor[floor] * node_factor[node_type] * rhythm_modifier
```

### GameManager 改动点

- `difficulty_multiplier` 不再用公式 `1.0 + (wave-1)*0.15`，改为
  `floor_factor[floor] * node_factor[node_type]`，由 `RouteGenerator` 在开层时写入。
- 新增 `run_route` 字段（见上），随 `save_game()` / `load_game()` 序列化。
- 新增 `current_floor: int` 与 `current_node_type: NodeType`。
